# Requirements Alignment

Use this before planning a deck. Ask no more than three questions in one round, and do not ask for information that can be inferred reliably from supplied material.

## Priority

1. **P0 — Delivery job**: intended outcome, source material, output format, and whether this is creation or editing.
2. **P1 — Audience and use**: audience knowledge, venue, reading deck versus speaking deck, and decision the deck should enable.
3. **P2 — Scope**: slide count, deadline, content density, research depth, and required charts or diagrams.
4. **P3 — Visual constraints**: user template, brand, palette, examples, and stylistic preferences.

## Ask or infer

| Item | Ask when | Infer when |
|---|---|---|
| Goal | The requested outcome is ambiguous | The user names a concrete meeting, defense, pitch, or report |
| Audience | Different audiences would change terminology or depth | The supplied template or source material clearly identifies the audience |
| Slide count | There is a fixed time or page constraint | Use the slide-budget heuristic when no limit is implied |
| Visual style | No template or direction exists and the choice is material | A user template, brand guide, or reference slide is supplied |
| Research | Claims must be current or sourced | All content is user-provided and no external verification is requested |

## Communication rules

- Ask at most three concise questions in one message.
- State reasonable assumptions and continue when risk is low.
- Do not expose filenames, module names, npm commands, or internal planning vocabulary to the audience.
- Resolve conflicts in this order: factual integrity, user template/brand, audience readability, narrative coherence, stylistic preference.
