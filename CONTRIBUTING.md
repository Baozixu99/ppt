# Contributing

Keep the installed Skill lightweight and deterministic.

1. Open an issue or describe the failure mode the change addresses.
2. Put repeated or fragile operations in tested scripts, not copied Markdown snippets.
3. Keep detailed variants in `references/`; keep `SKILL.md` focused on routing and workflow.
4. Run `node tests/validate-skill.js` and `node tests/smoke-test.js`.
5. For visual changes, attach rendered before/after slides and document the QA performed.
6. Do not add copied templates, fonts, or images without documented redistribution rights.
